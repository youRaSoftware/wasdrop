## 0. Что в `assets_pack/` и что с ним делать

Контуры — исходник для полигонов стенок и для отрисовки; в приложение как SVG **не кладём**: геометрия переводится в Dart-описание (`JarShape`), рисуется `CustomPainter`, в физику — цепочка коробок. Причина: стакан красится цветами темы и должен масштабироваться по высоте под экран, а стенки Box2D нужны в мировых координатах.
- `fx/` — совпадает с текущим, ничего не делать.
- `ASSETS.md` — описания шрифтов/тем устарели (уже реализовано), актуальна только секция «Заказы и Стаканы»: разлоки **Ваза/Чаша/Полка открыты**, Колба 10★, Наклон 15★, Часы 20★, Качели — «скоро» (v1.2); панель заказов 56 pt между HUD и стаканом; компакт для SE — кольца; звёзды — единая валюта. Мокапы 11a–11f в дизайн-проекте (в репозитории их нет).
- После переноса `assets_pack/` из корня удалить (в корне только CLAUDE.md и README.md по правилу проекта; папка не в git).

## 1. Стаканы (Этап A, ≈3 сессии) — ✅ сделано 2026-09-17

Звёзды пока всегда 0 — до этапа B открыты только 4 стакана.

### A1. Домен: `JarShape`
`domain/lib/models/jar_shape.dart`: `id`, `starsToUnlock` (0 — открыт), `comingSoon`, `wallPath` — контур **внутренней** стенки как список отрезков/дуг в **нормированных** координатах SVG (внутренняя область 290×510 → 0…1 по X, 0…1 по Y), плюс `extras` (полка, платформа). Мировые координаты получаем: `x_w = nx · 360`, `y_w = ny · worldHeight`. Пропорция стакана на экране остаётся от виджета (1.5–1.7): формы слегка растянутся по высоте, это допустимо (арки чаши/часов станут чуть выше — визуально нормально).
`JarShapes.all` (8), `byId`, `defaultId = 'classic'`. Контуры из SVG переводятся один раз вручную в код: кривые `C`/`Q` дискретизируются в 8–12 отрезков (скрипт `script/svg_jar_to_dart.py` в помощь, результат коммитится как Dart-константы).

### A2. Физика: `buildJarWalls` → `buildJarBody(world, shape, width, height, topMargin)`
- Стенки — по-прежнему толстые статические коробки (40 ед.), но не 3, а цепочка: каждый отрезок контура → четырёхугольник, выдвинутый **наружу** на толщину (нормаль отрезка). Стыки перекрываются (сегменты продлеваются на половину толщины), чтобы фрукт не цеплялся за шов. Polygon Box2D ≤ 8 вершин, выпуклые — четырёхугольники подходят.
- Верх боковых стенок продолжается на `wallTopMargin` (300) как сейчас.
- Полка (shelf) — отдельная коробка со скруглением через `Polygon(radius:)`.
- `userData: JarWalls()` для всех.
- Сплеш и меню остаются на прямоугольнике (передают `JarShapes.classic`).
- Тест: для каждого стакана уронить фрукты t1–t5 в 7 точках по ширине и проверить, что все уснули **внутри** контура (point-in-polygon по контуру) и не ниже дна; для vase/flask — что фрукт, брошенный у края, скатывается, а не застревает.

### A3. Отрисовка: `JarPainter` в `GameForm._Jar`
- Сейчас `_Jar` — `DecoratedBox` с бордером и `ClipRRect`. Заменить на `CustomPaint` (заливка `theme.jarFill` по внутреннему контуру, обводка `theme.jarWall` шириной `jarWallWidth` **снаружи** контура) + `ClipPath` по контуру для `GameWidget` (фрукты не выходят за стекло). Холст `GameWidget` остаётся прямоугольником 360 × H, внутри него — форма; мир и раньше был прямоугольным, ничего в движке для рендера менять не надо.
- Пикер-миниатюры: тот же `JarPainter` в 72×108 с 3–4 фруктами (`BallView`) на фиксированных позициях из `JarShape.previewFruits`.

### A4. Движок под форму
- `_clampAim`: диапазон X подвешенного фрукта — по **ширине горла на высоте `spawnY`** (`JarShape.openingAt(ny)`), а не по `worldWidth`; иначе у вазы/колбы фрукт висит в стенке.
- `_spawnInside` и `merge()` зажимают новый фрукт по **ширине контура на его высоте** (та же функция) вместо `0…worldWidth`.
- `clearTopLayer` без изменений (по Y). `shake` без изменений.
- `_restore`: `b.x.clamp` по контуру на высоте.
- Линия проигрыша `deadlineY = 96` — рисовать от стенки до стенки по контуру на этой высоте.
- Прицел (рейкаст) уже находит наклонные стенки.

### A5. Выбор стакана и сохранение
- `SettingsModel.jarId` (Hive `jarId`, default classic) — «последний выбранный»; `GameSnapshot.jarId` (партия помнит форму, восстанавливаем стенки до шаров).
- Экран `/jars` (`features/lib/jars/`: `JarsCubit`, `JarsScreen`, `JarPicker`): сетка 2×4 карточек (миниатюра, название, замок «10 ★» / «Скоро»), звёзды вверху; тап открытого → сохранить `jarId` и `goNamed('game')`; закрытого — подсказка. Вход: из меню строкой «Стакан: Ваза ▸» (и иконка `jar`), из паузы кнопка «Сменить стакан» (действует на новую партию).
- Названия — ключи `jars.<id>` на 6 языков.

## 2. Заказы (Этап B, ≈3 сессии) — ✅ сделано 2026-09-17

Итог: домен (`Mission`, генератор по уровню, трекер с тестами), кубит (награды, звёзды в прогресс, замена, снимок), `MissionsPanel`/`MissionCard` (+ компакт кольцами), `MissionsOverlay`, `MissionToast` с конфетти, строка звёзд на проигрыше, кнопка «Заказы» в паузе, переводы ×6, тесты кубита и смоук-сценарий (панель → оверлей, выполнение → тост → звезда в прогрессе). Открытые вопросы дизайна (§ 7 ТЗ) закрыты по факту: панель над стаканом, три заказа, звёзды — единая валюта.

### B1. Домен
- `MissionType` (enum): `getFruit`, `collectFruits`, `mergeStreak`, `combo`, `economy`, `bonusBomb`, `score`, `clean`. `Mission` (`id`, `type`, `tier?`, `target`, `progress`, `reward: MissionReward`), `MissionReward` (`bonus: Bonus?`, `points`, `stars = 1`).
- `MissionGenerator(random, difficulty)`: три заказа, разных типов, по уровню (`level = totalMissionsDone`): 0–5 — только getFruit t3–t5 / score 500 / streak 3; дальше — тяжелее. Для daily — `Random(seed)`.
- `ProgressModel` (новый Hive-бокс `progressBox`, `ProgressRepository`): `stars`, `missionsDone`, `missionsDoneToday` + дата, `unlockedJarIds` (вычисляемо из stars, но храним для «скоро»/подарков), `onboardingDone`.

### B2. События из кубита → `MissionTracker`
Кубит уже получает всё нужное: `onMerge(tier)` (получен `produced`), `onDropped()`, `useBomb()`/`useUpgrade`, счёт, `overLine` (нужен новый сигнал из движка: «касание линии» — `overLineTime > 0` → `cubit.onLineTouched()`). Трекер в `GameState.missions: List<Mission>`; серия = слияния между бросками; комбо = ≥2 слияний до следующего броска; economy = счётчик бросков от начала заказа.
Выполнение: `stars += 1`, награда (заряд → `shakes/bombs/upgrades + 1`, очки → `score`), `missionsDone += 1`, новый заказ на место; событие в `GameState.completedMission` (одноразовое, для всплывашки). Заказы — в `GameSnapshot.missions` (Map). Восстановление — как есть.

### B3. UI
- `MissionsPanel` под `GameHud` (56 pt; на высоте экрана < 700 — компакт с кольцами `CustomPainter`): три `MissionCard` (иконка: `BallView` фрукта / `AppIcon(bomb|streak|combo|star)`, текст, прогресс-полоска, «+1 ⚡» бейдж), состояния: обычная / последний шаг (пульс) / выполнена (галочка) / въезжает (`AnimatedSwitcher`).
- `MissionCompletePopup` — 1 с, `AppOverlay` не подходит (блокирует), делаем `Overlay`-тост над стаканом с конфетти (`CustomPainter`, 20 частиц палитры) и `Unbounded` заголовком.
- Экран `MissionsOverlay` (из паузы и по тапу на панель): три заказа полностью + награды, «Выполнено сегодня / всего», звёзды.
- Экран проигрыша: строка «★ +3 · до Колбы 4 ★».
- Тексты заказов — ключи `missions.<type>` с `{n}`/`{fruit}` (fruit через `FruitLabel`), 6 языков.

## 8. Риски
- Фрукт у наклонной стенки (flask, slope) может «дрожать» на стыке коробок → перекрытие сегментов и `Polygon(radius:)` на стыках; проверить тестом A2.
- Высота стакана зависит от экрана: формы растягиваются по Y на 0–13 % (пропорция 1.5→1.7). Если чаша/часы выглядят вытянуто на iPad — ограничить `jarMaxAspect` до 1.6.
- Панель заказов забирает 56 pt: на 375×667 стакан ≈ 375×470 (пропорция 1.25) — фрукты крупнее относительно высоты, партия короче; компакт-панель обязательна для SE.
- `games_services` и StoreKit-конфигурация dev: Game Center в dev-схеме использует sandbox-аккаунт, на симуляторе входа может не быть — кнопки просто скрыты.
